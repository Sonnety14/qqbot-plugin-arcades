# 附近音游机厅 · 查舞萌 / 查中二

AstrBot 插件，版本 **v0.6.3**。私聊发送 QQ 位置卡片，在本地点位库中查找最近的 5 家舞萌 DX 或中二节奏机厅。查询不调用大语言模型，不依赖其他业务插件。

## 安装与首次配置

环境：AstrBot **4.28.2 或以上**，建议使用其 Python 3.12 运行环境；QQ 适配器需能接收 OneBot location 消息或腾讯地图 JSON 位置卡片。业务模块仅依赖 Python 标准库。

1. 在 AstrBot 插件管理中使用仓库地址安装：`https://github.com/Sonnety14/qqbot-plugin-arcades`。也可以将仓库内容放入 `data/plugins/astrbot_plugin_arcades/`，再重载插件。
2. 打开插件配置，将 `platform_id` 填成 AstrBot 消息平台中实际的 **平台实例 ID**。不是 QQ 号，也不是适配器类型；留空时插件不处理消息。
3. 在 AstrBot 中设置管理员账号。首次安装没有点位数据库，管理员私聊发送 `恢复音游同步`，启用 nearcade 来源。
4. 调度器每小时检查一次；等待同步，或启用来源后重载插件触发启动检查。发送 `音游地图状态` 查看同步结果，再测试查询。

默认公开来源是 [nearcade](https://nearca.de)，通常无需地图账号、密码或高德 Key。需要网络访问其 `/api/shops` 接口。插件不附带全国店铺数据库，不承诺安装后立即有完整数据。无法访问上游时，也可由管理员手动增加点位。

## 普通用户使用

私聊机器人：

1. 发送 `查舞萌` 或 `查中二`。
2. 收到提示后，在 **3 分钟内**用 QQ 聊天框的“位置”功能发送位置卡片。
3. 机器人返回距离最近的最多 5 个点位，包括店名、地址、直线距离、编号和来源。

| 命令 | 作用 |
| --- | --- |
| `查舞萌` | 查询附近舞萌 DX 机厅 |
| `查中二` | 查询附近中二节奏机厅 |
| `取消音游操作` | 退出正在进行的查询或管理操作 |
| `音游地图状态` | 查看本地点位数量、来源状态和最近同步情况 |

仅支持私聊，群聊发送命令会提示转私聊。截图、实时位置共享和任意地图网址不作为定位输入。每个用户同时只保留一个操作，新命令覆盖旧操作；单独发送位置不会猜测要查哪个游戏。

距离使用 GCJ-02 坐标计算球面直线距离，**不是步行或驾车路线距离**。关闭的店铺、没有目标游戏或没有可靠坐标的记录不会参与有效排名；结果仅代表已有可用点位。出发前请核实营业时间、机台数量和机况。

## 管理员维护

权限采用 AstrBot 的管理员判断，QQ群管理员身份本身不授予插件管理权限。以下命令同样只在私聊使用。

### 增加点位

先发送 `增加舞萌` 或 `增加中二`，再发送以下任一种内容：

- QQ 位置卡片：根据卡片中的名称、地址和坐标直接保存。
- `店名 | 完整地址 | 纬度,经度`：直接保存，坐标须为 GCJ-02，顺序是纬度在前。例如 `示例机厅 | 示例城市示例路1号 | 30.00,104.00`，仅为格式示例，不能用于实际导航。
- `店名 | 完整地址`：需要配置高德 Web 服务 Key。插件解析地址后展示坐标预览，回复 `确认添加` 才保存。只接受唯一且达到门牌号、门址或兴趣点级别的结果。

人工点位使用独立来源，不会被同步覆盖。

### 删除点位

发送 `删除舞萌` 或 `删除中二`，再发编号、店名、地址关键词或 QQ 位置卡片。位置卡片只匹配 200 米内点位。插件先显示最多 5 个候选，再发送 `确认删除 完整编号` 删除其中一条。

来源点位的删除会保存为本地屏蔽记录，后续同步不会恢复相同编号；若上游改用新编号，需要重新核对。删除不修改上游网站，不批量删除。

### 同步配置

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| `platform_id` | 空 | 必填；限定一个 QQ 平台实例 |
| `sync_enabled` | `true` | 开启调度；关闭后仍可查询已有数据 |
| `nearcade_enabled` | `true` | 允许调度 nearcade；首次还需管理员启用来源 |
| `legacy_scrape_enabled` | `false` | 历史网页抓取兼容开关；新安装请保持关闭 |

nearcade 成功同步后，默认至少间隔 **25 天**才再次更新；失败时按 **UTC 日期**限制每天尝试一次，调度器每小时检查。`恢复音游同步` 会启用来源、清除来源阻断和当天尝试标记，但不会强制绕过 25 天成功同步间隔，也不会绕过上游验证。

兼容模块 `sources.py` 还保留旧 BEMANICN 网页抓取逻辑，默认不运行，旧来源也不参与最近机厅排序。不要将打开旧开关当作 nearcade 故障的解决方法。

### 可选：高德地址解析

只在管理员录入没有坐标的地址时需要 Key。用户查询位置不会发给高德。

在 AstrBot 数据目录下的 `plugin_data/astrbot_plugin_arcades/credentials.json` 写入：

```json
{"amap_key": "填写你自己的高德Web服务Key"}
```

也可以复制仓库的 `credentials.example.json` 后填写。根据部署系统限制文件权限，仅让 AstrBot 服务账号读取；不要把真实 Key 放进代码或提交到 Git。程序按需读取该文件，未配置时仍可用 QQ 位置或明确经纬度增加点位。默认每日地址解析上限为 1000 次，失败请求也计数，同时受高德自身额度限制。

## 实现方法

1. **输入解析**（`locations.py`）：仅识别支持的 QQ 位置组件，验证坐标范围和数值，统一经纬度顺序；不抓取卡片中的外部链接。
2. **交互状态**（`main.py`）：按“平台实例 + 用户”隔离三分钟操作窗口，校验私聊和管理员权限；写入前再次校验权限，删除必须确认候选编号。
3. **本地查询**（`store.py`）：SQLite 保存点位、来源与屏蔽记录；Haversine 公式计算距离后排序，最多返回 5 项。查询过程不需要 LLM 或在线导航 API。
4. **公开来源读取**（`nearcade_client.py`）：分页 GET `/api/shops`，限制响应体、页数、重试次数和请求频率。按照游戏系列 ID 分类：舞萌 DX 为 1，中二节奏为 3；旧版 maimai 的系列 2 不默认归入舞萌 DX。
5. **完整性检查**（`nearcade_snapshot.py`）：检查分页总数、重复页、重复编号、异常结构、空结果和数量骤降，防止把第一页误当作完整数据。验证失败时保留已有可查询数据。
6. **快照发布**（`snapshot_store.py`、`nearcade_sync.py`）：先建立独立快照，再更新查询库；人工点位和本地删除记录独立保留。两个 SQLite 库之间不是单一原子事务，异常退出后应检查状态并重新同步。

上游要求验证或拒绝访问时停止本次读取，不尝试绕过。分页规模、接口格式和坐标基准可能随上游变化；同步检查通过不代表每一家店的实际营业状态都已核实。

## 数据与隐私

运行数据位于 AstrBot 数据目录下的 `plugin_data/astrbot_plugin_arcades/`：

- `arcades.sqlite3`：点位、人工录入、本地屏蔽、地址解析缓存与调度状态。
- `nearcade.sqlite3`：来源状态、版本快照与完整性信息。
- `credentials.json`：可选的私有凭据。

查询者的位置用于本次内存计算，不写入上述数据库；操作会话内使用用户 ID 隔离请求。管理员主动添加的店铺地址和坐标会保存。AstrBot、适配器和 QQ 自身可能保留消息历史或日志，应独立配置其保留策略。

本仓库不包含 QQ 号、群号、平台实例身份、服务器地址、真实凭据、数据库、生产日志或个人账号资料。公开 GitHub 作者署名与仓库地址用于项目归属。

更新插件只替换代码，保留运行数据；备份前先停止 AstrBot，再复制两个数据库及凭据文件。不要直接复制正在写入的 SQLite 数据文件作为完整备份。

## 测试与开发

在仓库根目录执行：

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

测试使用合成数据与临时数据库，不连接 QQ、地图服务或 LLM。若要运行命令链路检查，请使用已经安装 AstrBot 的 Python 环境：

```bash
python scripts/check_arcades_plugin.py
```

## 常见问题

- **完全不响应**：先核对 `platform_id`、插件启用状态、私聊环境，以及平台消息是否到达 AstrBot。
- **没有点位**：首次需要启用来源并完成同步；查看 `音游地图状态`。也可手动录入点位测试。
- **有数据但结果很少**：该游戏分类中可能缺少坐标，或本地名单不完整；不要把部分结果理解为全国完整排名。
- **要求重新发位置**：使用 QQ 的“位置”卡片，截图和实时位置共享不受支持。
- **上游访问失败**：保留旧库，检查网络和来源状态；不要删除数据库或绕过验证来重试。
